# 智途紧急定位短信设计

## 目标

将现有“仅拨打紧急联系人”升级为一键安全闭环：用户提前在“我的”页面保存紧急联系人；点击紧急呼叫按钮或导盲杖上报紧急信号后，Android 客户端立即拨打该联系人，并通过手机短信发送求助信息。短信优先包含手机定位、定位精度和地图链接；定位不可用时仍发送明确的无定位求助短信，不能延迟电话呼叫。

## 已确认约束

- 定位来自 Android 手机的 GPS/网络定位，不宣称导盲杖内置 GPS。
- 短信由手机 SIM 卡直接发送，不经过 Django 或 DeepSeek。
- 联系人必须预先保存在 `UserPrefs/emergency_phone`。
- 手动按钮和导盲杖紧急信号复用同一套处理流程。
- 保留 Java + XML、`minSdk 24`、`targetSdk 35`，不增加地图 SDK。
- 首次使用需要电话、短信和定位运行时权限；电话或定位权限被拒绝时，仍执行当前已获授权的安全动作。

## 交互流程

1. 紧急页显示已保存的联系人和“管理联系人”入口，不在紧急页临时编辑号码。
2. 用户点击“发送定位短信并呼叫”，不再弹出二次确认框。
3. APP 检查 `CALL_PHONE`、`SEND_SMS`、`ACCESS_FINE_LOCATION` 和 `ACCESS_COARSE_LOCATION`。
4. 权限满足后同时启动两个动作：立即拨打电话；并尝试获取最近的手机位置后发送短信。
5. 有位置时短信包含“智途紧急求助”、经纬度、精度和 `https://maps.google.com/?q=纬度,经度` 链接。
6. 无位置、定位服务关闭或定位超时时，发送“当前无法获取定位”的求助短信。
7. 导盲杖信号触发时执行同样流程，并停止当前轮询，防止重复触发。

## 代码边界

- `EmergencyMessageBuilder`：纯 Java，负责生成有定位和无定位短信，便于 JVM 单元测试。
- `EmergencyActivity`：联系人展示、权限、定位、短信、电话和服务器轮询编排。
- Django `IsCallView`：读取后立即清零紧急信号，确保一次上报只触发一次。
- `ProfileActivity`：继续作为联系人唯一设置入口。

## 错误处理

- 没有联系人：不拨号、不发短信，跳转到联系人设置入口。
- 没有电话能力：仍尝试发送短信，并在页面显示电话不可用。
- 没有短信能力或短信权限：仍拨打电话，并显示短信未发送。
- 定位不可用：发送无定位版本短信，不等待网络地址解析。
- 短信较长：使用 `SmsManager.divideMessage` 和分段发送。
- 后端不可达：只影响导盲杖信号监听，不影响手动紧急按钮。

## 验收

- JVM 测试覆盖有定位短信、无定位短信和地图链接格式。
- Django 测试覆盖紧急信号触发后首次读取为 1、第二次读取为 0。
- Android `testDebugUnitTest`、`lintDebug`、`assembleDebug` 全部通过。
- 实机验证首次权限、短信实际送达、地图链接、直接拨号和导盲杖信号各一次触发。

## 非目标

- 不在服务器保存联系人或位置。
- 不接入收费地图、导航或短信云服务。
- 不承诺无 SIM 卡、欠费或系统限制下短信一定送达。
