# 出行助手 DeepSeek 风格界面设计

## 目标

将出行助手改为安静、清晰、适合长文本阅读的对话界面。视觉上参考 DeepSeek 的轻量对话布局，但继续使用智途的绿色品牌色，不复制其品牌元素。

## 页面结构

### 顶部栏

- 保留返回、自动播报开关和清空对话三个操作。
- 标题继续使用“出行助手”，不增加营销说明。
- 自动播报开启时显示扬声器图标；关闭时显示静音图标。
- 点击图标切换自动播报设置，关闭时立即停止当前朗读，状态与“使用设置”页面同步。
- 切换后显示并朗读“自动语音播报已开启”或“自动语音播报已关闭”。

### 快捷问题

- 保留“刚才识别到了什么”“现在适合过马路吗”“我有点紧张，陪我聊聊”三个问题。
- 使用浅色填充的建议胶囊，增加内边距和控件间距。
- 横向滚动，不压缩或截断中文。

### 消息列表

- 助手消息左对齐，显示“智途助手”来源标签，正文使用浅灰绿色对话框、淡灰边框和 8dp 圆角。
- 用户消息右对齐，显示“我”来源标签，正文使用浅绿色气泡。
- 消息正文使用 `18sp`，来源标签使用 `14sp`，行距增加到 `5dp`。
- 单条消息最大宽度为屏幕可用宽度的约 88%，避免过窄导致频繁换行。
- 消息之间保持明确的垂直间距。
- TalkBack 继续朗读“你说”和“出行助手说”，来源标签本身不产生重复焦点。

### 输入区

- 使用白色底部操作栏，与消息区通过细分隔线区分。
- 输入框改为圆角、浅灰底、无外露矩形描边，提示语为“向智途助手提问”。
- 输入文字使用 `18sp`，最小高度 `56dp`，最多三行。
- 语音和发送按钮均扩大到至少 `56dp`，保持明确的 TalkBack 标签。
- 请求处理中禁用输入按钮，并在输入区上方显示“正在分析”。

## 颜色与状态

- 页面背景使用现有浅色背景；助手对话框使用 `#F1F5F4`，边框使用 `#D5DFDC`，正文保持高对比深色。
- 用户消息使用浅绿色容器和深绿色文字，不使用大面积深色。
- 网络失败时保留用户问题并显示可重试状态，不清空输入。
- 不增加渐变、装饰图案或额外卡片。

## 实现边界

- 不修改 Django、DeepSeek API、对话请求模型和历史记录逻辑。
- 重构 `item_chat_message.xml` 和 `ChatMessageAdapter`，按角色控制布局、标签和背景。
- 调整 `activity_assistant.xml`、相关颜色、样式和字符串。
- 保留现有语音识别、TTS 自动播报、自动播报切换、清空对话和快捷提问功能。

## 验证

- 为消息角色显示逻辑提取纯 Java 展示模型并添加单元测试。
- 运行 `testDebugUnitTest`、`lintDebug` 和 `assembleDebug`。
- 检查消息文字在正常字体与应用大字体模式下均不重叠、不截断。
- 真机检查软键盘弹出后输入框、语音按钮和发送按钮仍完整可见。
