# Android 盲人无障碍改造设计

## 目标

让视障用户能够借助 Android TalkBack、语音播报和触觉反馈，独立完成客户端的四个核心任务：出行问答、交通灯识别、获取当前位置和紧急求助。地图、账号资料和服务器配置继续兼顾家属或明眼协助者使用。

## 设计原则

- 导盲杖的基础安全能力不能依赖手机客户端；客户端只提供联网增强能力。
- 关键功能必须能通过 TalkBack 顺序导航完成，不能只靠颜色、图标或视觉位置表达。
- 识别、定位、寻杖、联网和紧急呼叫等异步结果必须主动播报。
- 关键按钮同时提供清晰标签、较大触控区域和可选触觉反馈。
- 避免图标与相邻文字被 TalkBack 重复朗读。
- 不增加常驻麦克风监听，避免耗电、隐私和误触问题。

## 页面改造

### 首页

- 将品牌名和“功能”设置为无障碍标题。
- 四个核心入口作为完整可点击控件朗读，内容包括名称和用途。
- 装饰性图标从无障碍焦点中移除。
- 服务器状态变化时使用无障碍实时区域播报。
- 最近识别结果作为一个整体朗读，包含结果和更新时间。

### 出行助手

- 输入框、语音输入、发送和停止播报均提供明确标签。
- 请求处理中播报“正在思考”，回答完成后继续使用现有 TTS 自动播报。
- 网络失败时播报失败原因和可重试提示。
- 快捷问题提供完整的操作描述。

### 红绿灯识别

- 拍照按钮使用明确的“拍照并识别前方交通灯”标签。
- 相机就绪、识别中、红灯、绿灯、无法识别和网络失败均主动播报。
- 识别结果区域作为无障碍实时区域，颜色只作为辅助信息。

### 位置

- 地图不参与 TalkBack 焦点遍历，避免 WebView 内复杂地图元素干扰操作。
- 新增“播报当前位置”按钮，朗读地址、定位精度和更新时间。
- 获取位置成功、权限不足、定位关闭和定位失败均主动播报。
- 保留“打开地图”给家属或明眼协助者使用。

### 寻找导盲杖

- 发送中、发送成功和发送失败均主动播报。
- 成功时提供明显触觉反馈；失败后 TalkBack 焦点移动到“重新发送”。
- 页面文案明确该功能依赖导盲杖端对寻杖指令的支持。

### 紧急求助

- 紧急联系人、监听状态和操作结果使用实时区域播报。
- 发起操作时提供强触觉反馈。
- 权限缺失、联系人未设置、短信或电话部分失败时给出可理解的语音结果。
- 保持当前“一次操作发送定位短信并拨号”的流程，不增加视觉确认步骤。

### 我的与设置

- 账号信息作为一个整体朗读，敏感信息不在页面标题或无障碍描述中重复暴露。
- 所有设置分组使用无障碍标题。
- 开关朗读名称、当前状态和用途。
- 服务器测试结果主动播报。

## 实现结构

- 在 `BaseActivity` 中集中提供状态播报和不同强度的触觉反馈，避免各页面重复实现。
- XML 使用 `accessibilityHeading`、`accessibilityLiveRegion`、`importantForAccessibility` 和完整的 `contentDescription` 建立语义。
- 页面仅在重要状态变化时调用播报，避免 TalkBack 与 TTS 同时重复朗读同一内容。
- 新增纯 Java 文本格式化类，用于生成位置、识别和紧急状态的可测试播报文本。

## 错误处理

- 网络不可用时保留原页面状态，同时播报失败与重试方式。
- 权限被拒绝时说明缺少的能力，不静默失败。
- TTS 不可用时仍依靠 TalkBack 实时区域和屏幕文字反馈。
- 地图加载失败不影响定位地址和位置播报。

## 验证

- 为播报文本格式化和设置默认值补充单元测试。
- 运行 `testDebugUnitTest`、`lintDebug` 和 `assembleDebug`。
- 使用 Android 无障碍扫描规则检查缺失标签、小触控区域和重复焦点。
- 真机最终验收应开启 TalkBack，按首页、识别、位置、紧急求助四条路径完整操作一次。
